# QBO 03 Bank statements as ledger evidence: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bank statement lines are extracted, stored, matched to the documents they pay (by amount, date and the payee /
number in the narration), posted to the right bank account in the books without double counting, and reconciled per
account per month with a report PDF; an unreconciled statement month soft-blocks the month close.

**Architecture:** Gemini's extraction reply gains an optional `statement` object for `kind == "statement"`; a pure
`bank_statement.py` parses it and checks the running balance. Rows go to `aa_bank_statements` + `aa_bank_lines`
(FORCE RLS). A pure `bank_match.py` scores open items (from a pure `open_items` over the same `DocLine`s the books post)
and built-in / learned bank rules. The books engine takes matched lines as `Payment`s (with an explicit bank account)
and `BankPosting`s (charges, interest, transfers), replacing a document's `paid_on` payment so nothing posts twice. A
pure `bank_reconcile.py` compares the statement closing balance with the book balance of the account and lists
uncleared items; `books/bank.py` (async) glues DB, books engine and the PDF.

**Tech Stack:** FastAPI + SQLAlchemy async (Postgres JSONB), PyMuPDF, Next.js/React/TS.

**Spec:** `docs/superpowers/plans/2026-10-16-quickbooks-parity-plan.md` §3 "P1 — Bank statements become ledger
evidence, with reconciliation"; books design `docs/superpowers/specs/2026-10-09-autoaccounting-books-design.md`;
working rules `2026-10-16-qbo-parity-program.md`.

## Global Constraints

- New tables `aa_bank_statements`, `aa_bank_lines`, `aa_bank_rules`, `aa_bank_reconciliations` carry `enterprise_id` and
  get the firm policy in `rls.py` (`_FIRM_TABLES`); every query filters `enterprise_id` / company.
- Additive columns in the model **and** `schema.py`: `aa_accounts.bank_account_no VARCHAR(40) DEFAULT ''`,
  `aa_companies.review_flags JSONB DEFAULT '{}'`.
- Every bank mutation calls `audit.record` (new entities `bank_statement`, `bank_line`, `bank_rule`, `bank_reconciliation`).
- Never auto-link on amount alone; never auto-link when the narration names someone other than the payee.
- Extraction stays backward compatible: replies without `statement` still parse; old statement docs keep working.
- Theme CSS vars only, Hint on the new panel, page roots `lp`.

## Review Focus

1. A statement whose lines don't tie to the opening/closing balance (misread digit) must be flagged on the statement
   (`ties = false`, the breaking line numbers) and still stored — test in Task 2 (`test_tie_out_reports_the_breaking_line`).
2. Re-running the matcher must not undo a person's decision: confirmed / excluded lines are left alone and a rejected
   candidate is never re-proposed — test in Task 3 (`test_rejected_candidate_is_not_relinked`).
3. One open bill and two identical bank lines (e.g. a duplicate debit): the second line must not link to the same bill
   once its open amount is used — test in Task 3 (`test_open_amount_is_consumed_by_earlier_lines`).
4. A document with `paid_on` set *and* a bank match must post one payment, not two — test in Task 4
   (`test_bank_match_replaces_paid_on_payment`).
5. A statement for an account number that matches no bank account must not post anywhere until a person picks the
   account — test in Task 4 (`test_lines_without_account_do_not_post`) and Task 2 (`resolve_account` returns None).

### Task 3: Matcher and bank rules (pure `bank_match.py`)

**Files:** Create `services/accounting/bank_match.py`; Test `tests/test_aa_bank_match.py`.

**Interfaces — Produces:**
- `Candidate(kind, ref, on: date, amount: Decimal (open, >0), direction ("in"|"out"), payee, number, label,
  keywords: tuple[str,...] = ())`.
- `BankLineFact(id, on, amount (signed), narration, check_no, account_code)`.
- `Rule(pattern, direction, kind, account_code, payee_name, payee_tin)`.
- `Match(status, kind, ref, amount, posting: dict, candidates: list[dict], reason)`.
- `tokens(text) -> set[str]`, `name_tokens(text) -> set[str]` (minus bank / corporate / month stop words).
- `match_line(line, candidates, rules=(), rejected=frozenset(), own_accounts=()) -> Match`:
  1. exact-amount candidates in the window (−7 .. +90 days from the document date), same direction, not rejected;
     strong = payee token or document/check number in the narration (or a payee rule), conflict = narration names others.
  2. one strong → `matched`; several strong → `ambiguous`.
  3. none: partial = candidate with amount > line amount, payee hit and (number hit or "partial") → `matched` partial.
  4. posting rule (built-in: cash deposit → transfer from `cash` = `matched`; service/bank charge → `bank_charges`,
     interest → `interest_income`, ATM/withdrawal → `cash`, learned posting rules = `suggested`).
  5. weak (amount + window only) candidates → `ambiguous` (`bank_match_ambiguous`); else `unmatched`
     (`bank_line_unmatched`).
- `match_all(lines, candidates, rules, rejected: dict[line_id, set[ref]]) -> dict[line_id, Match]` — date order; a
  matched candidate's open amount is reduced so it can't be reused.
- `learn_rule(line, match) -> Rule | None` (from a confirmed match: payee rule when the narration had no payee hit,
  posting rule for postings; pattern = first ≤3 name tokens).
- `open_items(lines: list[DocLine], ewt, contributions, paid: dict[id, Decimal]) -> list[Candidate]`.

## Decisions

- **Narrations.** The plan gives no printed narrations; the eight lines use the QBO bank-feed CSV descriptions
  (`08_feed_bank_dec.csv`) verbatim, with check numbers 000818 / 000819 read from them. Opening ₱412,880.15 comes from
  the QBO opening JE (`09_journals.csv`).
- **Cash deposit is an auto-linked transfer; bank charges are a suggestion.** Acceptance counts the cash deposit among
  the 7 auto-links and only *suggests* Bank charges. A deposit of store cash moves money between the company's own
  accounts (Dr Bank, Cr Cash on hand: no P&L effect), so it auto-links; charges, interest and learned posting rules hit
  P&L and wait for a person. Unconfirmed suggestions don't post, so the acceptance test confirms line 8 before checking
  the ₱330,854.85 balance.
- **Never on amount alone.** An exact amount within the date window but no payee / number in the narration is
  `ambiguous` (`bank_match_ambiguous`, candidates listed), even with a single candidate.
- **Partial payments** auto-link only when the narration names the payee *and* the document number or says "partial".
- **Double counting.** A bank match is the document's payment: it replaces the document's `paid_on` payment. A
  document paid by a linked receipt isn't a candidate; the receipt is, and a match re-points the receipt's payment to
  the bank account and the line's date. Tax lines link to the filed return's payment (which already credits the bank)
  and journal matches link only; neither posts again.
- **Interest** posts net to Interest income (the 20% final tax withheld by the bank is not grossed up); a CPA can adjust
  by JE.
- **Lines with no resolved account** (account number matches no bank account by last 4) are stored but never post or
  match until a person picks the account on the statement.
- **Payroll** candidates are payroll documents; the narration keywords payroll / salary / salaries / wages count as the
  payee.
- **Close soft-block**: a month with a statement line in a bank account that has no active reconciliation for that
  month can't close unless an override reason is given; the reason goes into the close's audit event.
- **opening_balance_missing** is stored in `aa_companies.review_flags` (per account) and refreshed whenever statements
  are stored, rematched or reconciled; it shows as a banner on the Bank panel. Nothing is auto-posted to fix it.
- **Bank accounts** are the `bank` system account plus any active asset account whose `bank_account_no` is set (a
  sub-account per bank account); the number is typed in the chart editor.
- **Statement account assignment** is never guessed: an unknown number leaves the statement "Account not set" until a
  person picks the account; the number is then saved on that account so later statements resolve by last 4.
- **Reconciliation brought forward**: postings dated before the first statement (and the opening balances) are treated as
  already in its opening balance; outstanding items from before the first statement aren't listed (known gap).
- **Who may act**: any firm member can confirm / reject / reconcile (like document review); closing a month, and so the
  override, stays manager-only.
