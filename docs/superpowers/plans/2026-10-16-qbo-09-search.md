# QBO 09 Global search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One firm-scoped search across documents, contacts, bank lines, journal entries, tasks and companies, with a
type-ahead palette in the app shell ("/" or Cmd/Ctrl-K) and a full results page with filters and a Review queue filter.

**Architecture:** A pure parser (`services/accounting/search.py`) turns the query into text tokens plus detected
amount / TIN / date ranges / review reasons, and a pure scorer ranks rows. A router
(`routers/accounting_search.py`) builds one firm-scoped SELECT per group (ILIKE on indexed columns, equality on
amount / TIN / date), fetches a few candidates per group, ranks them with the scorer and returns grouped results with
navigation context. Frontend: `components/search/SearchPalette.tsx` in the Sidebar, `/accounting/search` page, and
deep-link params on `/accounting` parsed by a pure `lib/search-nav.ts`.

**Tech Stack:** FastAPI + SQLAlchemy async (Postgres, optional pg_trgm), Next.js / React / TS.

**Spec:** `2026-10-16-quickbooks-parity-plan.md` (P2 smaller wins, "Global search"), catalogue §0 Global search,
program rules in `2026-10-16-qbo-parity-program.md`.

## Global Constraints

- Every query filters `enterprise_id = scope_for(user)` (RLS is bound by `get_current_user`); no per-company access
  rules exist in the firm today, so firm scope is the whole rule.
- Additive indexes only via `services/accounting/schema.py`; pg_trgm only if the extension exists or can be created
  (guarded `DO` block, never fails startup).
- Short-query minimum: 2 characters after trimming, unless a structured value (amount / TIN / date) parsed or the
  review filter is on.
- Ids from URLs/events go through `safeId`; path segments through `seg()`.
- Theme CSS vars only, page roots `className="lp ..."`, page-guide Hint on the new page.

## Review Focus

- "1500", "1,500.00", "₱1,500", "P1,500", "PHP 1500" all find a ₱1,500.00 document and a −1,500 bank line.
- TIN in any format ("123-456-789", "123 456 789 000", "123456789") matches the 9-digit stored TIN.
- Ambiguous dates ("03/04/2026") match both 4 Mar and 3 Apr; "Oct 2026" / "2026-10" mean the whole month.
- `%`, `_` and `\` in a query are literal (LIKE escaping), and a 200-char query is cut, not an error.
- A document in another firm never appears (SQL compiles with the enterprise filter for every group).

## Decisions

- **Firm scope only.** No per-company access rules exist (staff see every client of the firm), so search filters by
  `enterprise_id` plus RLS; if per-company access is added later, the six builders are the place to add it.
- **Amount matches exact values only** (gross, VATable, VAT, withholding on documents; absolute amount on bank lines).
  No range or fuzzy amounts. Journal entries are not matched by amount (their lines are JSON strings in mixed formats);
  they match memo (particulars) and reference.
- **A bare number is searched both ways**: "1500" is an amount *and* text (document number "SI-1500" still matches).
- **Ambiguous slash dates** return both readings (MM/DD first, like PH forms); a month name or "YYYY-MM" means the
  whole month. Two-digit years are 20xx.
- **Date range filter** applies to dated groups only (documents: doc date, bank lines, journal entries, tasks: due date);
  contacts and companies are hidden while a date range is set. The **Review queue** filter shows documents only
  (needs review, not reviewed, not excluded, not deleted) and allows an empty query (most recent first).
- **Excluded documents are still found** (with an "Excluded" chip); deleted ones never are.
- **Ranking** is in Python over at most `limit × 4` candidates per group that SQL orders exact-first then newest;
  no relevance feedback ("thumbs").
- **pg_trgm** is created only if available and permitted; without it the same ILIKE queries run on plain btree indexes
  (correct, just slower on large firms). The dev DB has it available (1.6).
- **Shortcut "/"** is ignored while focus is in a text field; Cmd/Ctrl-K always opens.
